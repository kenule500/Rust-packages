What these metrics mean

Plain-language guide to the KPIs shown on each feature
◎ Traceability

How much of the feature is linked end-to-end — every requirement traced to a design, a task, and a test. 100% means nothing is orphaned.

100% — fully linked Partial — gaps remain 0% — nothing linked
✓ Verification

Whether the built code matches the approved spec. The system compares what was specified against what was implemented and reports the difference.

PASS — spec & code match WARN — extra, unplanned work FAIL — spec items missing NOT RUN — not checked yet
▤ Tests

Test coverage of the feature's acceptance criteria — the share of ACs that have a passing automated test behind them.

Complete — 100% of ACs Partial — some ACs untested NOT RUN — no tests yet
⛨ Gates

The four approval checkpoints a version must clear before it can ship. Each gate is signed off by a human reviewer.

Approved — signed off Pending — awaiting review In progress — being worked

Command Reference

Every command, explained in plain language

SpecDrive works through commands — short instructions you give to your AI assistant (slash commands) or to your terminal (CLI). Each one moves your project forward through a series of approval gates, so nothing is built until it has been clearly specified and signed off.

Don't worry about memorising them. Start with /sdrive:constitution to set the ground rules, then /sdrive:propose whenever you want to build something new. Click Details on any row below to see what it does, why it matters, and when to use it.
